**专栏⑯·第6篇：AI Agent 与工作流——智能体、ReAct、工具调用，从"聊天"到"做事"**

1000 问里 Agent 章节 2 问（Agent vs LLM 聊天、ReAct 循环）。这篇把 Agent 从"概念"带到"能搭一个自己的"——你记过的 AI 数字分身/智能体想法（4/14：一个数字教育的 AI 分身），本质就是一个 Agent。

**一、Agent 和 LLM 聊天的本质区别——"能自己决定调用工具"**

LLM 聊天：问 → 答。Agent：问 → **决定调用什么工具** → 拿到工具结果 → 再决定下一步 → 循环直到能回答。

**"决定调用哪个函数"的机制**：LLM 被训练成"输出 JSON 格式的函数调用请求"——当 prompt 里给出了工具列表（名称+参数描述+用途），模型会输出 {"name": "get\_weather", "arguments": {...}}，由运行时解析并执行，再把结果回填给模型。

**二、ReAct——思考-行动-观察的循环**

ReAct（Reasoning + Acting）：

思考：用户想知道今天能不能洗车 → 需要天气数据 行动：调用 get\_weather(city=上海) 观察：上海今天小雨，气温 22-28℃ 思考：下雨不适合洗车 → 可以回答 回答：今天上海有小雨，建议改天洗车

**跟人类解决问题一样**：不是一步到位，而是"想一下 → 查一下 → 再想"的迭代。

**关键**：Agent 的"思考"质量决定工具调用质量——prompt 里要让模型"先想清楚要什么数据、再决定调什么工具"，而不是瞎调。

**三、Agent 的四个组成部分**

1. **LLM 大脑**：决定"下一步做什么"（核心，其余都是围绕它）

2. **工具集**：函数/API/代码执行器——Agent 的能力边界由工具决定

3. **记忆**：对话历史 \+ 长期记忆（向量库/笔记）——Agent 记得住吗

4. **执行循环**：ReAct 循环/Plan-Execute 循环（先规划步骤再逐步执行）


**四、Agent 的三种落地形态（从轻到重）**

**1\. 单轮工具调用**：LLM + 几个函数（查天气/算数/搜笔记）——最简单，你日常就在用（我调 memo\_search 帮你翻笔记就是这种）

**2\. 多步 ReAct 循环**：能连续调多个工具完成一个任务（比如"整理这个主题的笔记并生成总结"——先搜→再读→再总结）

**3\. 自主 Agent（带规划）**：先拆任务清单，再逐步执行，最后汇总——复杂任务专用，但失控风险最高（需要人审）

**五、工作流——Agent 的"确定性版本"**

Agent 是"模型自己决定下一步"，\*\*工作流（Workflow）\*\*是"人画好流程图，每步调模型"：

输入 → 提取关键信息（LLM）→ 检索笔记（工具）→ 生成草稿（LLM）→ 人工审校（人）→ 输出

**区别**：工作流可预测、可控、容易 debug；Agent 灵活但不可预测。 **实战建议：能用工作流就别用 Agent**——你的"每日三问"就是工作流（定时→按专题出题→存笔记），不需要 Agent 的自由度。

**六、搭一个你自己的 Agent 数字分身——最小版本**

你 4/14 记过"数字教育的 AI 分身"。最小落地：

1. **工具集**：你的 flomo 笔记检索（memo\_search）+ 定时任务（cron）

2. **记忆**：你的 1000 问 + 卡片笔记 = 长期记忆库（RAG，第5篇）

3. **行为约束**：你的 instruction（每天问最重要的任务、回复一屏内、不灌鸡汤）——这就是 Agent 的"人设"配置

4. **执行循环**：固定工作流（晨间三问/晚间回顾/每周总结）


**关键认知**：Agent 分身的价值不在"像你"，在"遵守你的规则 + 调用你的资产"——规则（instruction）+ 资产（笔记）+ 工具（检索/定时）三件套齐了，分身就立起来了。

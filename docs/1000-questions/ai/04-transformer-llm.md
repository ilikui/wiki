1000 问里有 Transformer 和 LLM 基础的问题（Q/K/V、自注意力、涌现能力）。这篇把 LLM 从"会聊天"带到"知道它为什么能聊天"。

**一、Transformer 的核心——注意力机制**

**Q/K/V 到底是什么：**

- **Query（查询）**：当前 token 在"找谁"——我在生成"猫"字，我想知道上下文里哪个词跟我相关

- **Key（键）**：每个 token 的"被找到的标签"——我是"猫"这个词，我的特征标签是什么

- **Value（值）**：每个 token 实际携带的内容——我是"猫"，我携带的语义信息是什么


注意力分数 = Q·K 的点积 → softmax 归一化成权重 → 加权求和 V。直觉： **每个 token 问"上下文里谁跟我最相关"，然后按相关度加权吸收信息。**

**为什么说 Transformer 并行而 RNN 串行：** RNN 要按顺序一个一个处理 token（第 n 个依赖第 n-1 个的隐藏状态）；Transformer 一次性看到全部 token 同时计算（自注意力矩阵一步算完）。并行带来训练快（GPU 利用率高），代价是 O(n²) 的计算量——这是 Mamba 想解决的（1000 问里有）。

**位置编码为什么需要：** 并行处理意味着模型天然不知道顺序——"猫追狗"和"狗追猫"在并行输入下没有区别。位置编码（RoPE/绝对编码）把"位置信息"加进每个 token 的向量，让模型能区分顺序。

**二、GPT 的自回归 vs BERT 的双向**

- **GPT（自回归）**：只能看左边的词，从左往右逐词生成——所以适合"生成"

- **BERT（双向）**：同时看左右两边的词（掩码语言模型：盖住一些词让模型猜）——所以适合"理解"（分类/抽取）


**关键理解**：ChatGPT 是 GPT 家族——它生成每个词时"只看前面的词"。这就是为什么它会"顺着说"而不是"全局规划"——它没有"想好结尾再开头"的能力，只有一个词一个词往前滚。

**三、涌现能力——为什么 70B 突然会了 7B 不会的**

- 7B 模型做不了三位数加减法，70B 突然会了——这不是"学得更多"，是 **规模跨过阈值后出现了质变**（能力曲线不是平滑的，是突然跃升的）

- 涌现能力包括：链式推理（CoT）、指令跟随、少样本学习

- 工程含义： **模型能力不是"线性增长"的——选模型时别只看参数量，要测"目标任务上的涌现点"**


**四、训练三阶段——预训练 → SFT → RLHF**

**1\. 预训练（Pretraining）**：在海量文本上学习"下一个词是什么"。学的是语言本身（语法、知识、世界模型）。成本最高（GPU 月级）。

**2\. SFT（监督微调）**：用人工写的"高质量问答对"教模型"像人一样回答"。学的是 **格式和风格**——不是新知识。

**3\. RLHF（人类反馈强化学习）**：训练一个奖励模型（给回答打分），再用 PPO 优化策略——让模型学会"人类喜欢什么回答"。

**为什么不能跳过预训练只做 SFT：** SFT 是"在已有能力上调整行为"，不是"从零教知识"。没有预训练的知识底座，SFT 只是让模型学会"看起来很会回答"但内容全是编的。

**奖励黑客（Reward Hacking）：** RLHF 里模型可能发现"让奖励模型开心"的捷径（比如回答变长、变礼貌）而不是"真的更好"——这是对齐问题的雏形（1000 问 AGI 安全里有）。

**五、LoRA——为什么只训练 0.1% 参数就能微调**

全量微调要改所有权重（几 GB 的梯度）。LoRA 的核心洞察： **权重更新的有效秩很低**——只需要学一个低秩矩阵就能逼近全量微调的效果。

ΔW ≈ A·B（A 是 d×r，B 是 r×d，r 通常 8-64）。训练时只更新 A 和 B——显存占用从"全模型"降到"两个小矩阵"。

**工程含义**：一个 7B 模型全量微调要 4-8 张 A100；LoRA 一张就能跑。而且 LoRA 可以同时挂多个（每个任务一个小 adapter，推理时切换）——这是"一个底座、多个技能"的落地方式。

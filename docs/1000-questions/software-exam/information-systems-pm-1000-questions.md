# 软考高级·信息系统项目管理师：核心知识 1000 问

**软考高级·信息系统项目管理师：核心知识 1000 问**

▎ **信息化与信息系统**

1. 信息化"六要素"——信息资源、信息网络、信息技术、信息产业、信息化人才、信息化法规。为什么软考经常把这六个当作多选题的干扰项——其实考的就是你记不记得这六个"一个不能少"？

2. 国家信息化体系六要素的关系——"信息技术应用"是龙头、"信息资源"是核心、"信息网络"是基础、"信息技术和产业"是国家建设基础、"信息化人才"是成功之本、"信息化法规"是保障。如果一个选择题问"信息化的核心是什么"——选"信息资源"而不是"信息技术"？

3. 电子政务和电子商务的区别——G2G/G2B/G2C/G2E 和 B2B/B2C/C2C/O2O。为什么电子政务的"四类模式"中G2E（政府-公务员）容易被忽略？

4. 企业信息化规划的方法——关键成功因素法（CSF）、战略目标集转化法（SST）、企业系统规划法（BSP）。BSP的核心思想是什么——"自上而下地识别目标，自下而上地识别数据"？

5. 信息系统的生命周期——系统规划（可行性分析）→系统分析（需求分析）→系统设计（概要/详细设计）→系统实施（编码/测试/部署）→运行维护（修改/升级/退役）。软考问"可行性分析属于哪个阶段"——系统规划阶段，不是系统分析阶段？


**十大知识域·深入（上）**

▎ **整体管理**

1. 项目章程（Project Charter）和项目范围说明书有什么区别？章程是"授权项目经理使用组织资源"的文件——由项目发起人发布；范围说明书是"界定项目应该做什么"——由项目经理和团队制定。哪个先哪个后——章程先于范围说明书？

2. 项目整体变更控制流程——"变更申请→变更初审→变更方案论证→CCB审查→批准/否决→变更实施→变更验证→变更通知归档"。为什么CCB（变更控制委员会）不能是"一个人"——权力集中可能导致一人拍板无人制衡？


▎ **范围管理**

1. WBS（工作分解结构）的分解原则——"100%原则"（WBS的下层必须100%覆盖上层的工作）？为什么WBS的分解层次不能太细也不能太粗（太细：管理成本高；太粗：无法控制）？

2. 范围蔓延（Scope Creep）和镀金（Gold Plating）的区别——客户增加需求（范围蔓延）vs 团队主动增加功能（镀金）。为什么"镀金"通常比范围蔓延更难管理——因为这是团队"自作主张"？

3. 可交付物（Deliverable）——每个WBS元素必须对应一个可验证的可交付物。案例分析题里如果问"WBS分解哪里有问题"——常见答案：WBS元素没对应可交付物、分解粒度不一致、没有包含管理活动？


▎ **进度管理**

1. 关键路径法（CPM）——项目的"最短工期"等于关键路径上所有活动的工期之和。如果一条路径上有浮动时间（Float/Slack），说明它不是关键路径。为什么软考计算题里浮动时间算错了是最常见的失分点——公式：总浮动 = LS-ES 或 LF-EF，自由浮动 = min(后续活动的ES) - EF？

2. 三点估算（PERT）——活动历时 = (最乐观+4×最可能+最悲观)/6，标准差 = (最悲观-最乐观)/6。在±1σ内完成的概率是68.26%、±2σ是95.46%、±3σ是99.73%。如果题目问"在多久内完成的概率是95%左右"——要把范围差不多调整到±2σ？

3. 赶工（Crashing）和快速跟进（Fast Tracking）的区别——赶工就是加人（加资源、加成本），快速跟进就是串行改并行（可能有返工风险）。软考案例题里"你建议怎么压缩工期"——先判断是赶工还是快速跟进（如果资源够就赶工，如果资源不够就快速跟进，但要说清楚风险）？


▎ **成本管理**

1. 挣值管理（EVM）——PV（计划价值）、EV（挣值）、AC（实际成本）。三个基本值算出一堆指标：SV=EV-PV（进度偏差）、CV=EV-AC（成本偏差）、SPI=EV/PV（进度绩效）、CPI=EV/AC（成本绩效）。为什么软考计算题里很多人分不清PV和EV——PV是"计划了多少"，EV是"完成了多少"（不管花了多少钱）？

2. 完工估算（EAC）的三种计算公式——EAC=AC+(BAC-EV)（按原计划效率——CPI=1）、EAC=AC+(BAC-EV)/CPI（按当前CPI继续）、EAC=AC+(BAC-EV)/(CPI×SPI)（同时考虑成本和进度）。哪种情况下用哪个——如果当前偏差是偶发的用第一种，如果是趋势性的用第二种？


▎ **质量管理**

1. 质量保证（QA）和质量控制（QC）的区别——QA是过程审计（"做对了过程"），QC是产品检验（"做好了产品"）。软考论文里"你怎么做质量管理"必须同时写QA和QC——不能只写"我们写了很多测试用例"（那只是QC）？

2. 戴明的"PDCA循环"（Plan-Do-Check-Action）和朱兰的"质量三部曲"（质量计划-质量控制-质量改进）。怎么在论文里用PDCA框架来写质量管理实践？

3. 七种质量工具——因果图（鱼骨图）、流程图、直方图、帕累托图、散点图、控制图、检查表。案例分析题里如果问"要分析某个质量问题的原因，用什么工具"——鱼骨图。如果问"要判断过程是否受控"——控制图（超过上下限或七点同侧表示失控）？


**十大知识域·深入（下）**

▎ **人力资源管理**

1. 项目团队的五个阶段——形成（Forming）→震荡（Storming）→规范（Norming）→执行（Performing）→解散（Adjourning）。为什么"震荡期"是最危险的阶段（团队成员开始暴露冲突，如果项目经理压不住整个项目就散架了）？

2. 马斯洛需求层次（生理→安全→社交→尊重→自我实现）和赫茨伯格双因素理论（保健因素+激励因素）。论文里怎么用这些理论解释如何激励团队成员？


▎ **沟通管理**

1. 沟通渠道数 = N×(N-1)/2。N=10时沟通渠道是45条，N=20时是190条。为什么项目越大沟通效率越低——因为每增加一个人，沟通复杂度是指数级增长而不是线性增长？

2. 沟通的"五层次模型"（发送→编码→传递→接收→解码→反馈）。案例分析题里"沟通不畅的根本原因是什么"——常见答案：编码-解码不一致（用了专业术语对方听不懂）、反馈缺失（以为对方明白了其实没明白）？


▎ **风险管理**

1. 风险的"两个维度"——概率和影响。风险的等级 = 概率 × 影响。为什么不能只看概率（一个概率99%但影响极小的事件不是一个需要重点管理的风险）？

2. 风险应对策略——"回避"（改方案避开风险）、"转移"（买保险/外包）、"减轻"（加测试/加冗余）、"接受"（主动接受/被动接受——预留应急储备）。案例题里"你建议怎么应对这个风险"——先判断风险性质再选策略，选完要说明为什么选这个不选那个？


▎ **采购管理**

1. 合同类型的比较——固定总价合同（风险主要在卖方）、成本补偿合同（风险主要在买方）、工料合同（介于两者之间）。为什么政府项目倾向用固定总价合同（预算确定、风险转移给供应商）？

2. 招投标流程——招标→投标→开标→评标→定标→签约。时间节点要求（公告到开标不少于20天）——软考选择题常考这个数字？


▎ **干系人管理**

1. 干系人分析矩阵——权力/利益矩阵。四个象限的策略：高权力高利益（重点管理）、高权力低利益（令其满意）、低权力高利益（随时告知）、低权力低利益（监督即可）。论文里写"你如何管理干系人"——先做干系人识别再用这个矩阵分类，对不同类别用不同策略？


▎ **法律法规与标准**

1. 《中华人民共和国招标投标法》——什么情况下可以不招标（涉密/应急/单一来源/金额小）。金额阈值：施工单项合同400万以上、重要设备采购200万以上、勘察设计服务100万以上——这三类必须招标？

2. 《著作权法》——职务作品的著作权归属。员工在公司完成的软件——著作权归谁？（除非合同另有约定，否则归公司）。论文里如果写"我们自主研发了XX系统"——要说清楚"著作权归公司所有"？

3. 信息系统安全等级保护——五级：第一级（自主保护）、第二级（指导保护）、第三级（监督保护）、第四级（强制保护）、第五级（专控保护）。三级以上需要"每年测评"——软考选择题喜欢考等级和保护级别的对应关系？


▎ **案例分析高频题型**

1. 计算题必考——关键路径+挣值分析+三点估算。三大块各怎么练？关键路径：画网络图找最长路径（千万别数错节点）；挣值：按题目给的PV/EV/AC代公式（注意单位一致）；三点估算：套PERT公式算期望和标准差。计算题值45分（3道案例每题15分计算类）——拿不到就危险了？

2. 找错题——"请分析该项目在XX管理中存在的问题"。答题模板：先写明理论要求（"根据PMBOK，XX管理应该包含XX"），再对照题目逐条指出问题（"题目中……说明在XX上存在问题"），每条都要有"理论依据+原文证据"——不能只写"沟通有问题"？

3. 论文准备——提前准备3-4篇高质量的"背稿"。怎么写——选你最熟悉的领域知识域（进度/风险/质量），准备一个"万能项目背景"（最好跟你工作相关的嵌入式/汽车电子项目，因为是你的真实经验，论文答辩时不会被问倒），把八股结构练熟？


▎ **高频考点速查**

1. 论文最常考的六大管理方向——进度管理（考频最高，因为有计算基础）、风险管理（第二高，好写套路）、质量管理、范围管理、整体管理、人力资源管理。为什么进度管理论文最好写——可以用WBS+关键路径+甘特图+挣值管理串起整篇论文，既有理论又有实操？

2. 软考综合知识里"新技术"板块的考法——云计算（IaaS/PaaS/SaaS）、大数据（Hadoop/Spark）、物联网（架构）、区块链（共识机制）、人工智能（机器学习类型）。为什么这些新增的"新技术"题每年都在增多——因为出题人在逐年更新题库，想看你有没有跟上技术发展？

3. 软考高级通过的关键——选择题不低于45分、案例不低于45分、论文不低于45分。大部分人挂在哪一门——论文（35%通过率）？为什么案例（65%通过率）反而没那么多人挂——因为计算题做对了就稳了一半？

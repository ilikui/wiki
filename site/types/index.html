    1000 问知识体系｜Flomo 汇总入口¶

    将 Flomo 中围绕「1000 问 / 1000 个问题 / 堆问题学习法」的知识资产集中到 Wiki，作为长期维护的总目录。原始 Flomo 笔记保留为来源与追溯入口；本页负责统一导航、学习方法、专题边界和后续沉淀规则。

    核心方法：先提出问题，再组织答案¶

    堆问题学习法不是一次性写出 1000 个完美问题，而是先建立领域问题地图，再按知识结构、难度和关联逐步回答。

    1. 选领域与边界：明确目标、使用场景和知识范围。
    2. 建立问题地图：先铺开基础概念、原理、机制、工程实践、故障排查与演进趋势。
    3. 分层分类：按专题归档；避免问题只按产生时间堆积。
    4. 逐题回答：回答应包含结论、原理、示例/证据、适用边界和常见误区；暂时不会的标记待查。
    5. 建立双向链接：关联先修知识、工程案例、代码、规范与其他问题。
    6. 实践验证：通过实验、项目、测试或真实案例验证答案。
    7. 周期回顾：补充新问题、合并重复问题、修正过时答案，并记录验证日期。

    两类问题设计¶

    • 深挖型（技术树）：面向 AUTOSAR、C、嵌入式等专业领域。重点追问 Why / How、边界条件、时序、异常路径、工具行为和量产故障。
    • 铺开型（知识面）：面向历史、文化、通识等领域。先建立 What / Who / When / Where 的全景，再逐步深入原因、影响与争议。
    • 考试型：数学、软考等先按课程体系建立定义、定理、关系和典型题，再补应用题；不机械地把“先列 1000 问”套用于所有学科。

    AUTOSAR 1000 问：专题地图¶

    • 基础与架构：AUTOSAR 的目标、分层、RTE、SW-C、VFB、配置与代码生成。
    • 通信栈：Signal/PDU、COM、PduR、CanIf、CanTp、CAN/LIN/FlexRay、SOME/IP、DoIP、CAN FD/XL。
    • 网络管理与 ECU 状态：EcuM、BswM、ComM、CanNm、唤醒、休眠、Partial Networking。
    • 诊断：Dcm、UDS、DID、DTC/DEM、诊断会话、安全访问、刷写、CAN TP 与 DoIP。
    • 非易失存储：NvM、MemIf、Fee、Fls、Block 类型、掉电一致性、写入策略。
    • OS 与多核：任务/中断、Schedule Table、IOC、Spinlock、内存保护、核间通信。
    • 功能安全与信息安全：ISO 26262、ASIL、E2E、WdgM、SecOC、Crypto、HSM、OTA 与回滚。
    • 工具链与工程化：DaVinci、EB tresos、ARXML、配置依赖、Pre-Compile/Link/Post-Build、生成代码审查、CI。
    • 运行时排障：报文不发送、周期抖动、RTE 数据不刷新、Bus-Off、初始化顺序、链接失败。
    • 平台演进与集成：Classic/Adaptive、Linux 共存、ROS 2 对比、版本迁移、变体管理、测试与验证。

    从 Flomo 到 Wiki 的沉淀规则¶

    每个问题建议使用统一结构：

    1. 问题：一句话表达具体疑问。
    2. 简答：先给结论，再解释原因。
    3. 原理 / 流程：必要时用 Mermaid 图、时序图或分层图。
    4. 示例：代码、配置片段、报文、公式或真实案例。
    5. 边界与误区：说明版本、平台、前提和容易误判的地方。
    6. 验证方式：测试方法、实验步骤、规范章节或可信来源。
    7. 关联问题：链接到先修问题、相邻专题和工程案例。
    8. 来源与状态：保留 Flomo 原文链接，标注“待回答 / 初稿 / 已验证 / 需更新”。

    去重与迁移原则¶

    • 不删除 Flomo 原笔记；Wiki 是整理后的知识库，Flomo 是原始捕获与历史来源。
    • 相同问题只保留一个主条目；其他版本作为补充、案例或来源链接。
    • 不把“问题清单”误标成“已回答”；答案和验证状态分开记录。
    • 保留原始术语、标准版本、时间和工程上下文；遇到相互矛盾的答案时记录差异，不强行合并。
    • 每个专题维护一个索引页；避免把所有内容挤进单一超长页面。
    • 采用相对路径链接，方便 GitHub 浏览及后续迁移到个人 Wiki/数字花园。

    来源与方法论笔记¶

    • 堆问题学习法：先列问题、分类、逐一回答、重复问题继续深挖、定期回顾。
    • 我的知识管理体系总览：输入 → 整理 → 存储 → 输出 → 实践 → 反馈的循环。
    • AI 与知识管理：从 1000 问到个人知识库闭环：将问题库、卡片笔记和 AI 整理流程连接起来。
    • 1000 问：技术树深挖与知识面铺开的区别：不同领域采用不同的问题设计策略。
